# AI 执行与迭代

1. 读取用户目标与现有项目，保护已有功能和用户修改。路由/框架/品牌由任务决定，V2 不强迫迁移技术栈。
2. 建立 reference-brief：来源、授权、设备、状态、可观察事实、推断和未知。无参照时选择原创方向。
3. 查 page-patterns，建立路由和状态矩阵；specification 只是要求，不得写为完成。复杂表格、交易、Agent 分别调用专项。
4. 先实现语义结构、组件状态和主路径，再建立 tokens、响应式、动效和 3D 增强。示例数据始终标明。
5. 实际运行。关键操作必须有有效反馈或明确未接入状态；错误保留输入，副作用重试前查原请求状态。
6. 固定视口、字体、数据、浏览器和运动偏好截图。运行差异工具检查整体和关键区域，人工复核构图与信息层级。
7. 迭代预算默认 3 次；每次写问题、变更、前后图、测量和剩余差异。不修改基准以掩盖失败。
8. 按验收契约记录 passed/failed/blocked/not_run。交付范围、启动命令、证据与未测项。只有用户要求部署时才部署。

## 示例任务
“使用 awwwards-enterprise，为现有项目实现客户目录，包含全量搜索、分页、编辑冲突恢复和 viewer 权限展示；保留既有 API。先阅读实际项目，最后给出运行证据和服务端授权检查结果。”

“使用 awwwards-design-intelligence 和 visual-reconstruction，从我有权使用的截图提取区域和 tokens，在现有框架重建；缺少字体时用许可明确的替代，列为差异；不要凭截图编造后台与隐藏状态。”

## 架构移植
原生模块示例用于演示行为与独立启动。移入 React/Vue 时，将 domain.mjs 视为逻辑参考，页面状态交给框架；effect cleanup 对应动效/3D dispose。不要在组件中重新挂 document 级委托监听器。框架构建和真实 API 接入必须重新测。
