# Contributing

Use issues for concrete defects or missing page/state patterns. Include the page or skill, expected/observed behavior, environment and a minimal reproduction. Do not post credentials or private screenshots.

Keep business simulation boundaries visible, preserve existing V1 interfaces, and distinguish specification coverage from actual implementations. Add focused checks for changed behavior. Run the relevant commands in README before opening a pull request; browser results and screenshots must describe the environment actually tested.

Use original or appropriately licensed assets and retain third-party notices. Do not update a visual baseline merely to hide a failure. Test in a working copy because evidence files are regenerated.
